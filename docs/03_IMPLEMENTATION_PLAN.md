## Phase 2 — Cleaning, profiling, validation  ⚑ Opus review

**Goal:** any raw frame becomes a cleaned frame, a `DatasetSchema` and a list of `ValidationIssue`s.

**`preprocessing/cleaning.py` — `DataCleaner`:**
- `fit(X)` builds a per-column plan, stored in `self.plan_: dict[str, str]` with values `numeric_string | boolean | datetime | category | keep`. It records `feature_names_in_`.
  - Object columns: strip, then replace `MISSING_TOKENS` (case-insensitive) with NaN. If at least 95 % of non-null values parse as numbers after removing `Rs.`, `LKR`, `$`, `,`, `%` and spaces, the column is `numeric_string`. If every non-null lowercase value is in TRUE/FALSE tokens, it is `boolean`. If at least 90 % parse with `pd.to_datetime(errors="coerce", format="mixed")` and the name or values look date-like, it is `datetime`. Otherwise it is `category` (with optional case normalisation: `str.strip().str.title()` when `normalize_category_case`).
  - Numeric columns that contain only {0,1} stay numeric. The profiler treats them as boolean.
- `transform(X)` applies the plan to a **copy** (never mutates the input). Missing columns are added as NaN. Unparseable values become NaN. Output dtypes: float64, boolean→float (0/1/NaN), datetime64, object.
- `get_feature_names_out`. Supports `set_output(transform="pandas")`.

**`data/profiler.py`:**
- `infer_feature_type(s, n_rows)` follows the order of Architecture §5: constant → identifier → boolean → datetime → numeric (but a numeric column with ≤ 10 unique integer values and low unique ratio is still NUMERIC, with a warning "low-cardinality numeric — consider categorical") → text → categorical.
- `profile_dataset(df_clean)` returns a `DatasetSchema` with skewness (scipy, numeric only), IQR outlier ratio, sample values and warnings (`mostly_missing`, `high_cardinality`, `identifier`, `constant`, `low_card_numeric`).

**`data/validation.py`:**
- `validate_target` implements the FR-2 rules (errors and warnings).
- `suggest_problem_type`: a non-numeric target, or one with ≤ 10 unique values, suggests classification; otherwise regression.
- `detect_leakage`: for each feature against the target (on a sample of at most 20k rows):
  - (a) numeric: absolute Pearson/Spearman correlation ≥ `LEAKAGE_CORR` for regression; for classification, the single-feature ROC-AUC (OvR macro) ≥ `LEAKAGE_AUC`.
  - (b) missingness indicator: AUC/|corr| ≥ the threshold. This catches `disconnection_date`.
  - (c) categorical: a 1-to-1 mapping to the target (a groupby nunique of 1 covering at least 98 % of rows, where categories have more than 1 row on average).
  - (d) a column equal to the target.
  - Each finding is `ValidationIssue("warning","leakage", msg, column)`.
- `check_supported` returns errors for fewer than `MIN_ROWS` rows, no usable features, or all-text features.

**Tests** (`tests/unit/test_cleaning.py`, `test_profiler.py`, `test_validation.py`):
- `"Rs. 1,250"` → 1250.0; the input frame is unchanged after transform; an unseen column order and an extra column are handled; a missing column becomes NaN.
- The boolean variants map correctly; `"?"` becomes NaN.
- Type inference on each conftest column matches what is expected.
- On the generated samples, `detect_leakage` flags `disconnection_date` (churn) and `total_bill_lkr` (LOS) and does **not** flag `tenure_months` or `age`.
- `validate_target`: regression on a string column gives an error; classification with a class smaller than `cv_folds` gives an error.

## Phase 3 — Preprocessing engine (recommender + builder)  ⚑ Opus review

**Goal:** `PreprocessingConfig` plus a `ModelProfile` produce a leakage-safe `ColumnTransformer`. This is the most heavily graded part.

**`preprocessing/transformers.py`** (all `BaseEstimator, TransformerMixin`, pandas-friendly, with `get_feature_names_out`):
- `DatetimeFeatures`: for each datetime column outputs `_year, _month, _dayofweek, _dayofyear, _days_since_ref`. `ref_` is the train minimum, learned in `fit`.
- `OutlierClipper(method="iqr", factor=1.5)`: learns bounds in `fit`, clips in `transform`.
- `SkewCorrector`: wraps `PowerTransformer(method="yeo-johnson", standardize=False)` applied only to columns whose train |skew| > threshold, which is decided in `fit`.
- `BooleanToFloat`: casts to 0/1 floats.
- `TextStats` (optional): character length and word count.

**`preprocessing/recommender.py` — `recommend_config(schema, target, problem_type, leakage=())`:**
- Applies the rule table in Architecture §5. Every `ColumnConfig.reason` is filled in, and `explanations` gets a dataset-level summary: rows/cols, duplicates, imbalance and target transform decisions, and excluded columns with reasons.
- For classification, the imbalance decision needs the target distribution. Add the optional argument `y: pd.Series | None` (and update §4.2).

**`preprocessing/builder.py` — `build_feature_transformer(config, profile)`:**
- Resolves `"auto"` per profile:
  - **TREE:** numeric uses `SimpleImputer(median, add_indicator=config.missing_indicator)` with no scaling. Low-card categorical uses `SimpleImputer(constant "__missing__")` then `OrdinalEncoder(handle_unknown="use_encoded_value", unknown_value=-1, encoded_missing_value=-1, min_frequency=rare)`. High-card uses `TargetEncoder(target_type=auto, random_state)`. Datetime uses `DatetimeFeatures` then a median imputer. Boolean uses a most-frequent imputer.
  - **SCALE_SENSITIVE:** numeric uses imputer → `OutlierClipper` (if outliers) → `SkewCorrector` (if transform) → scaler (standard/robust/minmax). Low-card uses imputer → `OneHotEncoder(handle_unknown="infrequent_if_exist", min_frequency=rare, sparse_output=False)`. High-card uses `TargetEncoder` → `StandardScaler`. Datetime uses features → imputer → scaler. Boolean uses imputer.
- Explicit user overrides (anything not `"auto"`) win in both profiles.
- Groups columns that share the same resolved recipe into a single transformer each, using sub-pipelines inside the `ColumnTransformer`. `remainder="drop"`, `verbose_feature_names_out=True`, `set_output(transform="pandas")` where every step supports it (`TargetEncoder` and `OneHotEncoder` do in sklearn 1.5).
- Raises `ValueError("No usable features…")` if nothing is included.
- Provides `describe_pipeline(config, profile) -> list[dict]` (column, type, steps as text) for the UI.

**Tests** (`tests/unit/test_transformers.py`, `test_recommender.py`, `test_builder.py`, `tests/integration/test_leakage_safety.py`):
- Each transformer: fit on train, transform on test with unseen and missing values, no crash, feature names correct.
- Recommender on `messy_df`: the id and constant columns are excluded, the skewed column gets yeo_johnson, the date column gets datetime features, and every reason is non-empty.
- Builder: for both profiles, `fit_transform` on train and `transform` on a test set that contains **unseen categories, all-NaN rows and shuffled columns** gives finite output of a fixed width. The tree profile has no scaler and the scale-sensitive profile has no ordinal encoder.
- **Leakage test:** a `SpyTransformer` that records `len(X)` seen in `fit`, placed in the pipeline. `cross_validate` with k=5 on the train split asserts that every recorded fit size is at most 0.8 × len(train) and that the test rows never reach `fit`.
- **Generalisation test:** recommend → build → `fit_transform` succeeds without errors on `load_breast_cancer`, `load_wine`, `load_diabetes`, a `make_classification` frame with injected categorical/missing/date columns (no network downloads), and both Sri Lankan samples.

## Phase 5 — Training & evaluation engine  ⚑ Opus review

**`training/pipeline_factory.py` — `build_model_pipeline(model_key, config, y=None)`:**
- Builds `imblearn.Pipeline([("cleaner", DataCleaner(...)), ("features", build_feature_transformer(config, spec.profile)), ("sampler", ...optional), ("model", estimator)])`.
- Imbalance:
  - `class_weight` is set on the estimator if it is supported. For xgb binary, `scale_pos_weight = neg/pos` is computed from `y`.
  - `smote` → `SMOTE(random_state, k_neighbors=min(5, minority-1))`; `undersample` → `RandomUnderSampler`.
  - For ensembles, a sampler falls back to class_weight on each base.
- Regression with `target_transform="log1p"` wraps the pipeline in `TransformedTargetRegressor(func=np.log1p, inverse_func=np.expm1)`.
- Voting/stacking/hybrid keys delegate to `ensembles.py`.

**`evaluation/metrics.py`:** `scoring_map` (sklearn scorer names; for binary, set `pos_label` = encoded minority class via `make_scorer`), `compute_metrics` (every metric in Definition §9; ROC-AUC/log-loss only when probabilities exist; MAPE only when there are no zero targets; NaN-safe), `default_primary_metric`, `GREATER_IS_BETTER` map.

**`training/trainer.py` — `train_models(df, config, model_keys, primary_metric=None, progress=None)`:**
1. Select the `included()` columns plus the target. Drop rows with a missing target and exact duplicates. Record the counts in `run.notes` (add a `notes: tuple[str,...]` field to `TrainingRun` and update §4.1).
2. Classification: `LabelEncoder` fits y; `class_labels` stores the original labels as strings.
3. `train_test_split(stratify=y if classification)`.
4. For each key: `progress(key, i, n)`, then `cross_validate(pipe, X_train, y_train, cv=StratifiedKFold|KFold(shuffle, rs), scoring=scoring_map, n_jobs=1, error_score="raise")`, then `fit` on the full train set (timed), then predict/predict_proba on test (timed), then `compute_metrics`. Any exception gives `ModelResult(status="failed", error=short message)` and the loop continues.
5. Returns a `TrainingRun` with `versions` (sklearn, xgboost, lightgbm, catboost, pandas, python).
- `leaderboard()`: columns `model, cv_<primary>_mean, cv_<primary>_std, test_<metric>..., fit_s, predict_s, status`. Sorted by primary, respecting greater-is-better (RMSE and MAE are reported as positive values; scorers use `neg_` internally and the sign is flipped for display).

**`evaluation/importance.py`:** `permutation_importance` on the **full pipeline** with raw `X_test`, so importances are on the original columns. `n_repeats=5`, and subsample X_test to at most 2,000 rows. Returns a DataFrame `feature, importance_mean, importance_std` sorted.

**`evaluation/plots.py`** (pure plotly; no Streamlit): `leaderboard_bar`, `cv_boxplot`, `confusion_matrix_fig` (with labels), `roc_fig` (binary plus OvR for multiclass), `pr_fig`, `pred_vs_actual_fig`, `residuals_fig`, `importance_fig`, `class_distribution_fig`, `missingness_fig`.

**Tests:**

## Phase 6 — Inference & persistence

**`inference/predictor.py` — `Predictor(pipeline, config, schema, class_labels)`:**
- `input_spec()`: for each included feature, gives `{name, type, default, options (categorical: top 50 seen values), min, max}` from the schema.
- `validate_input(df)`: missing required columns is an error. Extra columns give a warning and are dropped. All-NaN rows give a warning.
- `predict_one(record)`: builds a 1-row DataFrame and returns `{"prediction": label_or_value, "probabilities": {label: p} | None}`.
- `predict_batch(df)`: returns a **new** frame with `prediction` and, for classification, `proba_<label>` columns. Labels are decoded with `class_labels`.

**`inference/persistence.py`:** `save_bundle(path, result, run, schema)` dumps `{pipeline, config, schema, class_labels, metrics, versions, created_at, tabulaml_version}` with joblib to `artifacts/<model>_<timestamp>.joblib`. `load_bundle(path)` checks that the keys are present, warns if the sklearn version differs, and returns a `Predictor`.

**Tests:** `tests/integration/test_predictor.py`:
- Train rf on churn, then `predict_one` with a record that contains an **unseen district and a missing value** returns a valid label, with probabilities summing to 1.
- Batch with shuffled and extra columns works; batch missing a column gives an error issue.
- Save → load → identical predictions.
